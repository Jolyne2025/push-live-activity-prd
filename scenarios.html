1. Core Judgment: Live Activity is a Persistent State, Not a Message Alert

Live Activity fits scenarios where a user is actively tracking an ongoing state that evolves over hours; it does NOT fit one-off event notifications. This makes inquiry-related transaction status tracking the natural home for Live Activity on our platform. By contrast, existing push message alerts (e.g. "new message received") are instant events — push already covers them well, and a persistent LA would waste Dynamic Island / Lock Screen real estate. Apple also prohibits displaying message bodies on the Lock Screen.

2. Candidate Scenarios Around the Inquiry Lifecycle

Buyer + Seller sides across the inquiry funnel. Phase-1 candidates are starred (★). The pre-inquiry phase (discovery/browsing) is not recommended — there is no user-initiated activity to bind, and marketing is banned by Apple.

PhaseScenarioTrigger (user action)Live Activity ContentPriority
Post-inquiry B1 — Inquiry awaiting seller reply Buyer submits inquiry / Contact Supplier Persistent card: "Inquiry sent — waiting for the seller to reply" + elapsed wait time; status auto-updates: sent → seller read → seller replied. Tap opens the conversation thread. ★ Phase-1
B2 — Quote validity countdown Buyer receives a quote from the seller Shows the quoted amount + remaining validity countdown (local timer, no network cost); urgency drives faster buyer decisions. Expires automatically or shifts to Lock Screen state when time runs out. ★ Phase-1
B3 — RFQ quote aggregation Buyer publishes an RFQ Aggregated "N quotes received so far" card, updated in real time as quotes arrive. Analogy: Airship sports multi-event aggregation (3.7x engagement). Phase-2 candidate
At / Post-inquiry W1 — New-inquiry aggregation (seller) Seller receives a new inquiry (first inquiry triggers LA start) Persistent aggregation: "N new inquiries pending, M/N handled" — updated in real time. Replaces per-message MESSAGE_SENT pushes, reducing notification fatigue. ★ Phase-1
W2 — Quote viewed receipt (seller) Seller sends a quote Quote sent → buyer viewed the quote → "viewed" status updated; prompts the seller to follow up when a quote is viewed but not yet replied to. Phase-2 candidate
Pre-inquiry (NOT recommended) Any LA during discovery / browsing — No user-initiated "tracking action" to bind to. Marketing strategies (RECOMMENDATION / RFQ_marketing / TRENDING) are explicitly banned by Apple. Skip

3. Explicitly NOT Suitable for LA (Keep Push)

  • One-off "new message" alerts — instant events, push suffices. Apple prohibits message bodies on the Lock Screen. LA can only show aggregated states like "N new messages", wasting screen real estate for no gain.
  • Marketing / promotions / recommendations (RECOMMENDATION / RFQ_marketing / TRENDING) — banned by Apple.
  • One-shot receipts (e.g. read receipts) — no persistent state to track.
  • High-frequency content — LA has a limited update budget (~4KB payload, throttle on frequency).

  • Apple HIG / ActivityKit: Live Activities are designed for "ongoing tasks the user is actively tracking" (workout, order, flight, timer) — isomorphic with inquiry status tracking.
  • Airship 2024: QSR order-tracking LA customers saw +50% more sessions; sports apps with LA devices saw 3.7x sessions (aggregation pattern).
  • Pushwoosh / OneSignal use-case library: Countdown (limited-time offers, flash sales) and progress tracking (delivery, crowdfunding) are the two dominant LA patterns — both require an explicit user action to start.
  • Visable data: ~7,866 island-capable users (47.9% of iOS). 99.95% are iOS 17+ where LA follows push permission automatically (no extra prompt). Full sizing report available.

5. Recommendations

Phase 1 — 3 scenarios: B1 (inquiry awaiting reply, buyer) + B2 (quote countdown, buyer) + W1 (new-inquiry aggregation, seller). All three satisfy the "user action + ongoing state" principle and can reuse existing strategy_ids (UNANSWERED, MESSAGE_SENT) and the by-push-id attribution pipeline.
