一、核心判断：Live Activity 是「常驻状态」，不是「消息提醒」Key judgment: LA is a persistent state, not a message alert

Live Activity 适合「用户主动跟踪、持续数小时、状态会推进」的场景；不适合「一次性事件提醒」。 因此围绕询盘（inquiry）前中后的交易状态跟踪是 LA 的主场，而「通知已有的 push 消息提醒」（如新消息到达）不适合用 LA 承载——即时事件用一次性 push 即可，常驻界面反而挤占灵动岛/锁屏，且 Apple 禁止在锁屏展示消息正文。
维度 DimensionLive Activity（灵动岛/锁屏常驻）Push Notification（一次性通知）
本质 Nature正在进行的状态 ongoing situation一次性事件提醒 one-off event
生命周期8h 灵动岛 + 4h 宽限（锁屏合计 12h），最长可设 16h秒级/分钟级消失
触发要求必须用户主动行为触发（Apple 红线）服务端随时可发
内容限制锁屏不显示敏感数据（消息正文不可上岛），仅聚合状态可带标题/正文（有大小限制）
典型形态倒计时 / 进度条 / 状态推进 / 多事件聚合新消息、交易提醒、营销触达
营销场景Apple 明令禁止（促销/优惠/广告）允许（需授权）

三、明确不适合 LA 的场景（维持 push）Explicitly NOT for LA — keep push

  • 新消息到达逐条提醒：即时事件，push 已覆盖；且 Apple 禁止锁屏展示消息正文，LA 只能显示「有 N 条新消息」这类聚合状态，常驻反而挤占界面空间。One-off "new message" alerts — instant events, push suffices; message bodies cannot appear on Lock Screen.
  • 营销/促销/推荐类（RECOMMENDATION / RFQ_marketing / TRENDING）：Apple 红线，明确禁止。Marketing/promo/recommendation — banned by Apple.
  • 已读回执等一次性事件：事件本身无持续状态，无 LA 价值。One-shot receipts — no persistent state to track.
  • 高频变化内容：LA 更新预算有限（约 4KB / 每分钟有节流），不适合需要秒级刷新的内容。High-frequency content — LA update budget is limited.

五、建议 Recommendations

一期聚焦 3 个场景：B1 询盘等待回复（买家）+ B2 报价倒计时（买家）+ W1 新询盘聚合（卖家）。 全部符合「用户主动行为触发 + 持续状态跟踪」原则，且与现有 UNANSWERED / MESSAGE_SENT 策略可复用（strategy_id 继承、by-push-id 归因不变）。工单描述中「推送场景」表格待 Utkarsha 确认后按本参考填充。
注：本报告为场景设计参考，非行业实证数据——B2B 询盘场景的 LA 公开案例稀缺，映射逻辑基于「交易状态跟踪」「聚合」「倒计时」三类通用形态的行业数据外推，落地前建议以一期 AB 实验验证（实验方案已在工单中：iOS 16+ 用户 50% AB 两周）。
